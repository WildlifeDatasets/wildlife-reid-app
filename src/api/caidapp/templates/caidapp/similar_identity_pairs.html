Similar identity pairs

This search compares embeddings saved during identification initialization, which normally includes representative observations; it cannot reliably distinguish two identities in the same media file.

Identification dashboard

How this search works

  • The input CSV contains one row per observation with an assigned identity, including its bounding box when available. It also includes observations not marked as representative.
  • The search uses embeddings already stored during identification initialization, which normally processes representative observations. It does not calculate new embeddings from the bounding boxes in this CSV. Rows without a matching stored embedding are skipped.
  • MegaDescriptor ranks pairs from different identities by cosine similarity. Local feature matching then scores a shortlist by the number of matched points. Higher scores mean stronger similarity within that method; the two score types are not directly comparable.

Two observations in one media file have the same file name and may be assigned the same stored embedding. A pair from the same media file is excluded, but comparisons with other media files can still be misleading. Review both identities and media files before merging; this search never merges them automatically.
